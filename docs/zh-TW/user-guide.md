## 快速開始

以 DNS 放在 Cloudflare 為例，從零到一張會自動續期的憑證：

1. 登入後，在側邊欄選擇組織與專案。
2. **整合設定 → 新增整合 → 簽發者**：第一次測試請選「Let's Encrypt (staging)」，填入聯絡信箱並勾選同意條款。
3. **新增整合 → DNS**：選擇 *cloudflare*，貼上具有該網域 *Zone:Read* 與 *DNS:Edit* 權限的 API token。
4. **憑證 → 申請憑證**：名稱例如 `www`，網域名稱每行一個，簽發者與 DNS 供應商選剛才新增的。私鑰保存位置維持「在 Certower 伺服器上」，按 **送出申請**。
5. 一兩分鐘內狀態會變成「有效」。可以下載憑證鏈，或用 [Agent](#用-agent-部署) 自動部署。
6. 測試成功後，新增正式的「Let's Encrypt」簽發者並改用它。之後 Certower 會自動續期。

## 基本概念

| 名詞 | 說明 |
|---|---|
| **組織** | 一間公司或一個部門。底下有專案、共用的整合設定、憑證探索與成員。 |
| **專案** | 一起管理的一組憑證，例如「網站服務」或「ERP」。權限與 Policy 以專案為單位。 |
| **憑證** | 你希望存在的憑證：網域名稱、簽發者、金鑰類型、私鑰放哪裡。Certower 會簽發並持續續期。每次簽發產生一個**版本**。 |
| **簽發者** | 支援 ACME 的憑證機構（CA）帳號：Let's Encrypt、ZeroSSL、Google Trust Services、Sectigo、GlobalSign、DigiCert、TWCA 等。 |
| **DNS 供應商** | Certower 用來建立臨時 DNS 紀錄、證明你擁有網域（DNS-01 驗證）的憑據。 |
| **整合設定** | 簽發者、DNS 供應商或通知管道的設定。組織層級的設定由所有專案共用；專案層級的只給該專案使用。 |
| **Agent** | 安裝在你伺服器上的小程式，私鑰保存在該主機，並負責把憑證安裝到 nginx 等服務。 |
| **部署目標** | Agent 主機上安裝憑證的位置，例如「web-01 上的 nginx」。 |
| **Policy 護欄** | 限制專案能申請的內容：網域、CA、金鑰類型、萬用字元、效期。 |

## 登入

用電子郵件與密碼登入，或在管理員有設定時點「使用 … 登入」的單一登入按鈕。介面語言會跟著瀏覽器設定，也可以在登入頁或側邊欄底部切換（English、繁體中文、简体中文）。

- **變更密碼**：側邊欄 → **變更密碼**。你在其他裝置上的登入會被登出。
- **忘記密碼**：請系統管理員替你重設。
- 密碼連續輸錯多次後，會暫時無法登入幾分鐘。
- 每次登入有效 12 小時。

## 角色

你能做什麼取決於你在組織或專案中的角色。在組織層級授予的角色，適用於組織內所有專案。

| 角色 | 可以做的事 |
|---|---|
| **檢視者**（`viewer`） | 查看憑證與憑證探索結果。 |
| **操作人員**（`operator`） | 檢視者的權限，再加上使用既有的整合設定申請、續期、撤銷與部署憑證。 |
| **專案管理員**（`project_admin`） | 操作人員的權限，再加上管理整合設定與其機密、Agent 與部署目標、憑證探索端點、成員與 API token，以及查看稽核日誌。 |
| **組織管理員**（`org_admin`） | 所有專案的專案管理員權限，再加上建立專案與設定 Policy。 |
| **稽核人員**（`auditor`） | 檢視者的權限，再加上查看稽核日誌。 |

沒有任何內建角色可以匯出私鑰，這個權限只能透過自訂角色明確授予。**系統管理員**另外可以管理使用者帳號與建立組織。

## 串接 CA 與 DNS 供應商

開啟 **整合設定**（組織共用）或專案的 **專案整合設定**（只給該專案用；同名時專案設定優先），點 **新增整合**。

### 簽發者（CA）

| 欄位 | 說明 |
|---|---|
| CA preset | 選擇你的 CA，ACME 位址會自動帶入。其他 ACME CA 請選「自訂」。 |
| Contact email | CA 會把帳號相關通知寄到這裡。 |
| External Account Binding | ZeroSSL、Google Trust Services、Sectigo、GlobalSign、DigiCert、TWCA 需要。請從 CA 帳號後台複製 *Key ID* 與 *HMAC key*。 |
| I agree to the CA's terms | 必須勾選。 |
| Default ACME profile | 選填，例如 Let's Encrypt 的 `shortlived`。 |

帳號金鑰會自動產生。機密欄位加密保存，儲存後無法再查看；要更換時直接輸入新值即可。

台灣使用者請注意：TWCA 支援 ACME，需要 External Account Binding。中華電信（HiPKI／ePKI）在 2025/7/31 之後簽發的憑證已不受 Chrome 信任，且沒有公開的 ACME 服務；[憑證探索](#憑證探索找出沒有納管的憑證)會標示出這類憑證。詳見 [CA 支援狀況](../ca-support.md)。

### DNS 供應商

Certower 用 DNS-01 證明網域所有權：新增一筆 TXT 紀錄，等到查得到之後完成驗證，再把紀錄刪除。這種方式可以簽發萬用字元憑證，也適用於網際網路連不到的內部伺服器。

Cloudflare 請建立 API token（*My Profile → API Tokens → Create Token → Edit zone DNS*），只授權需要的 zone，權限為 *Zone:Read* 與 *DNS:Edit*。

## 申請憑證

**憑證 → 申請憑證**：

| 欄位 | 說明 |
|---|---|
| 名稱 | 簡短的識別名稱，例如 `www`。 |
| 網域名稱 | 每行一個，第一個會作為主體名稱。`*.example.com` 需要 Policy 允許萬用字元。 |
| 簽發者、DNS 供應商 | 從整合設定中選擇。 |
| 金鑰類型 | ECDSA P-256 是現代的預設選擇；需要支援舊用戶端時選 RSA 2048 以上。 |
| 私鑰保存在哪裡？ | **在 Certower 伺服器上**：加密保存、立即簽發，可下載成檔案。**在 Agent 的主機上**：在該主機產生、永遠不離開，綁定部署目標後才簽發。 |
| ACME 設定檔（Profile） | 選填，否則使用 CA 預設。 |
| 負責人信箱 | 誰負責這張憑證，會顯示在憑證頁面。 |

你會看到的狀態：

| 狀態 | 說明 |
|---|---|
| **等待簽發** | 尚未簽發（私鑰放在 Agent 的憑證則是在等待綁定部署目標）。 |
| **有效** | 已有有效的憑證。 |
| **失敗重試中** | 上次嘗試失敗，會以遞增的間隔自動重試（1 分鐘起，最長 6 小時）。頁面上會顯示錯誤原因。 |
| **需要處理** | 已停止簽發，需要有人排除原因，例如違反 Policy、申請被 CA 拒絕或設定不完整。 |

## 管理憑證

打開一張憑證，可以看到網域、私鑰、目前版本、續期時間、歷史版本與部署狀態。

- **自動續期**：在 CA 建議的續期時間窗內（ARI），或剩下三分之一效期時。「續期時間」會顯示預計的時間點。
- **立即續期**：馬上排入續期，例如修改網域名稱之後。
- **下載憑證鏈**：PEM 格式的憑證與中繼憑證。
- **撤銷**：請 CA 撤銷目前版本，需選擇原因（私鑰可能外洩時選「私鑰外洩」）。之後 Certower 會自動簽發替代憑證。
- **刪除**：Certower 停止管理這張憑證，並刪除保存的私鑰。這**不會**撤銷憑證，需要的話請先撤銷。

## 用 Agent 部署

使用 Agent 時，私鑰在你的伺服器上產生，每次續期後也會自動安裝並重新載入服務。

1. **Agent 與部署目標 → 新增 Agent**：取一個名稱（例如主機名稱），複製註冊指令。token 只能使用一次。
2. 由管理員（或擁有該主機 root 權限的你）安裝 Agent 並執行註冊指令，見[管理員手冊](admin-guide.md#安裝-agent)。完成後 Agent 會顯示「線上」。
3. 在該 Agent 上 **新增部署目標**：
   - **nginx**：填入完整憑證鏈與私鑰的路徑。Certower 會寫入檔案、執行 `nginx -t`、重新載入 nginx，並確認 `127.0.0.1:443` 已提供新憑證；失敗時會還原舊檔案。
   - **files（任何服務）**：寫入檔案，並可選擇執行主機允許的 reload 指令。
4. 在憑證頁面點 **綁定部署目標**。「部署狀態」區會顯示每個目標的狀態與錯誤訊息。

主機上的 `agent.json` 決定 Agent 可以寫入哪些目錄、執行哪些指令，所以指向其他位置的部署目標會失敗，並顯示清楚的原因。細節見 [Agent 說明](../agent.md)。

## 憑證探索：找出沒有納管的憑證

**憑證探索** 會檢查你的伺服器實際提供的憑證，包括手動購買的憑證、被遺忘的設備，以及其他團隊的憑證。

1. **新增端點**：每行一個，格式為 `host` 或 `host:port`（預設 443）。選擇一個專案（專案成員可以看到，告警也會送到該專案的通知管道），或整個組織。
2. Certower 會立即掃描，之後每 12 小時掃描一次。**立即掃描** 可以重新掃描。
3. 用「有問題」或「未納管」篩選，點一列可以看細節。

| 發現的問題 | 說明 |
|---|---|
| 已過期／即將到期／尚未生效 | 效期問題。 |
| 根憑證已不受信任 | 憑證鏈指向瀏覽器已不再信任新憑證的根憑證，例如 2025/7/31 之後的中華電信。 |
| 名稱不符 | 憑證不包含該主機名稱。 |
| 憑證鏈不受信任 | 缺少中繼憑證、自簽憑證或私有 CA。 |
| SHA-1 簽章、金鑰強度不足 | 過時的密碼學。 |
| 效期過長 | 超過簽發當時 CA/Browser Forum 的上限（2026/3/15 起 200 天、2027/3/15 起 100 天、2029/3/15 起 47 天）。 |

「已納管」表示伺服器提供的就是 Certower 簽發的那張憑證。

## 通知

**整合設定 → 新增整合 → 通知**：

- **webhook**：格式可選 *json*（附簽章，給你自己的系統使用）、*slack*（也適用 Mattermost 與 Google Chat）或 *discord*。
- **email**：填入 SMTP 伺服器、寄件者與收件者。

每個通知管道都可以限定事件類型與最低嚴重度。用 **傳送測試** 確認設定正確。事件：

| 事件 | 時機 |
|---|---|
| 憑證已簽發 | 每次簽發或續期後。 |
| 簽發失敗 | 某次嘗試失敗，或已停止簽發。 |
| 即將到期 | 到期前 21、14、7、3、1 天，以及到期當下。 |
| 部署失敗 | Agent 無法安裝或驗證憑證。 |
| 探索告警 | 掃描發現嚴重問題。 |

細節與 Webhook 簽章格式見[憑證探索與通知](../discovery-and-notifications.md)。

## Policy 護欄

組織管理員可以為每個專案設定 **Policy**：

- **允許的網域**：例如 `*.example.com` 允許 example.com 底下所有名稱。留空代表不限制。
- **允許的簽發者**：整合設定的名稱。留空代表不限制。
- **允許的金鑰類型**。
- **允許萬用字元憑證**：預設關閉。
- **最長效期（天）**。

不符合 Policy 的申請會被拒絕並說明原因；已存在但不再符合的憑證，在修正前會停止續期。

## 成員

**成員**（組織）與 **專案成員** 頁可以授予角色，對象可以是：

- **使用者（電子郵件）**：對方必須已經有帳號。
- **身分提供者（IdP）群組**：該 SSO 群組裡的每個人都會得到這個角色，權限自動跟著公司目錄服務走。
- **服務帳號**（僅限專案）：搭配 API token 做自動化。

你只能授予「你自己擁有其全部權限」的角色。

## 稽核日誌與工作佇列

- **稽核日誌**（組織）：每一筆變更是誰做的、何時、從哪個位址。需要專案管理員、組織管理員或稽核人員角色。
- **工作佇列**（專案）：背景工作清單，包括簽發、續期、通知與掃描，以及嘗試次數與最近一次錯誤。

## 常見問題

**Certower 能幫我續期目前付費 CA 的憑證嗎？** 只要該 CA 提供 ACME（現在大多都有，通常需要 External Account Binding）就可以。不支援的話，也可以透過憑證探索持續追蹤。

**Certower 停機一天會怎樣？** 不會有明顯影響：憑證會在到期前好幾週就續期，Certower 恢復後會繼續處理。

**私鑰放在哪裡？** 保存在伺服器上的私鑰，加密存放在 Certower 的資料庫；保存在 Agent 的私鑰，只存在該主機上。

**可以用 API 嗎？** 可以。介面上能做的事都可以透過 [REST API](../api.md) 完成，自動化請使用服務帳號的 token。
